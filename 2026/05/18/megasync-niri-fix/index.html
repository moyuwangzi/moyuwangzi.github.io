MegaSync 在 Niri (Wayland) 上的修复方案

发表于2026-05-18|更新于2026-05-18
|浏览量:

问题描述

  • MegaSync 在 Niri 环境下使用原生 Wayland 启动时直接崩溃（core dump）
  • 切换到 XWayland (xcb) 后能启动，但点击"添加同步"按钮时，对话框会坍缩为肉眼不可见的 1×1 像素

根本原因

两个独立问题叠加：

1. 崩溃问题

MegaSync 内部有 Wayland 检测代码。当 QT_QPA_PLATFORM=wayland 时，它在 createInfoDialog() 中尝试调用 xcb_intern_atom()（X11 操作），在纯 Wayland 环境下直接触发 segfault。

修复： 强制使用 QT_QPA_PLATFORM=xcb，让 MegaSync 通过 XWayland 运行。

2. 对话框 1×1 问题

MegaSync 使用 Qt5 + Qt Quick (QML) 构建 UI。Qt5 QML 窗口在初始化时有一个竞态问题：

  1. Qt5 创建 X11 窗口，立即向 X server 发送 WM_NORMAL_HINTS
  2. 此时 QML 内容还未加载，Qt5 使用默认尺寸 1×1
  3. WM_NORMAL_HINTS 中 min_size = max_size = 1×1 被写入
  4. QML 加载完毕后应该更新窗口尺寸，但在 XWayland (xwayland-satellite) 环境下这一步没有发生
  5. 窗口被永久锁定在 1×1，Niri 无法突破这个约束

修复： 用后台 watcher 脚本，检测到 max_size=1×1 后立即：

  1. xprop -remove WM_NORMAL_HINTS 移除约束
  2. xdotool windowsize 强制 resize
